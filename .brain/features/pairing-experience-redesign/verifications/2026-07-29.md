## Findings for main thread

1. **Dead focus ring on `link-submit` (the FAIL).** `app/routes/link.tsx:443-449`: the button combines `className={INK_KEY}` (which ends in `focus-visible:ring-2 focus-visible:ring-[#ffcc00]`, `link.tsx:210`) with `style={INK_KEY_STYLE}` whose inline `boxShadow: "inset 0 -1px 0 rgba(0,0,0,0.25)"` (`link.tsx:215`) wins over the ring utility's `box-shadow`. Probe evidence: `:focus-visible` matches, class present, computed shadow = inline value only. Fix options: drop `boxShadow` from the inline style into the class (so `focus-visible` variants can override), or compose the bevel into `--tw-shadow` so Tailwind's ring stacks with it. Note the same `INK_KEY + INK_KEY_STYLE` pairing is used for `link-open-controller` (`link.tsx:~423`) — likely the same dead ring there; worth fixing both.
2. Cosmetic only: none observed. The journey reads as one coherent dark object end to end except the intentional light login seam.

## Verdict rationale

FAIL on a single measured claim. Everything else — the /tv console restyle (exact rgb values for field/plate/readout/lamp, meta tags, QR URL), the /link rebuild (well/track colors, sr-only radios, pure-CSS segment reveal both with JS and with JavaScript fully disabled), the full feat-014 golden-path regression (prefill, create+name, success with amber lamp, TV flip with HttpOnly device cookie, controller mirror), the no-JS pairing contract, the login seam, role attributes, touch-target heights, and the bogus-code rollback — passes with exact observed values and zero console/network errors. But the spec explicitly requires a visible amber focus ring on the submit button and it does not render: the inline bevel shadow overrides the ring utility, making the ring dead code. That is a keyboard-navigation a11y defect on the primary action of the restyled page, so the walk cannot pass as-is.
