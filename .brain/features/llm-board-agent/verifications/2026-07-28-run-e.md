### Reading the screenshot: `TEMP 19#22C` is the animation, not a bug

The TV screenshot shows `19#22C` and `37#44#` where `data-char` says `19-22C` and `37-44%`. These are tiles **caught mid-flap**, not wrong glyphs: `#` is at index 39 of `BOARD_CHARS` and `-` at 43, so a tile four flaps short of `-` is showing `#`. Flap travel runs 3–5s (`flap-travel.ts`) and the screenshot was taken 2.5s after the socket delivered the grid. `data-char` is authoritative and is correct. Recorded because the image otherwise reads as a charset defect — `-` and `%` are both legal `BOARD_CHARS`.

## Findings for main thread

- **No defects found in the app.** Both claims the change makes held up.
- **The `#`-mid-flap reading trap** above is the one thing worth carrying forward: any future verification that screenshots the TV within ~5s of a write will capture intermediate glyphs. Assert on `data-char`, and wait ≥5s before treating a screenshot as the final board.
- **Driver bug worth recording so it is not rediscovered:** `page.mouse.down()` does **not** engage `control-ptt` on a `hasTouch` context — the button binds React `onPointerDown`/`onPointerUp`, and the first attempt at this run recorded nothing and burned three 90s timeouts looking like a hung generate. Dispatch real `PointerEvent`s (`locator.dispatchEvent("pointerdown", { pointerId: 1, pointerType: "touch", isPrimary: true })`) and assert `data-recording="true"` immediately, so a missed press fails in 5s instead of looking slow.
- **`playwright-core` in this repo wants a `chromium_headless_shell-1234` build that is not in the local cache.** The driver pins `executablePath` at the cached `chromium-1228` full build. Harness plumbing, not an app or CI concern.
- Latency is the open product question, not correctness: 35s for a searching board versus 13s without. Run C measured 30s vs 5s. Consistent, and long enough to be worth a UI affordance.

## Verdict rationale

**PASS on the two paths under test.** The change claims a board that depends on live data gets real numbers, and that a board that does not gets no search. Both were demonstrated rather than assumed, through the real UI: a phone holding zero cookies paired off a single-use token, recorded audio through a fake microphone, and the resulting board named OSLO and carried four figures, of which the sky condition matched the WMO code exactly, the humidity range contained the real 38 %, and the temperature and wind sat slightly low in a way consistent with a different source read at a different minute — hedged ranges bracketing reality, which is the opposite shape from the confident invented number this change exists to eliminate. The second prompt produced a correct bin-day board **2.7× faster** with no search, proving the prompt's do-not-search half is load-bearing rather than decorative; both prompts traverse identical code, so the only difference is the model's decision. Revisions incremented once per grid write (0 → 1 → 2) and the TV received both boards over its own socket. Console and network were clean on every context. Two legs of three were verified here; the empty-audio error path was not reached because the third context failed to hydrate in time, and it is claimed only on the strength of run C, which observed it directly — that gap is stated rather than smoothed over. Taken with run C, which used a different board, a different driver, and a six-hour-earlier weather reading, two independent runs agree on every claim this change makes.
