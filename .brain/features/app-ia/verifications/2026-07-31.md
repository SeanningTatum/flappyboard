## Findings for main thread

- `resolveSignedInHome`'s one-board branch is **not** exercised here — the seeded admin holds three boards, so this walk only ever saw the rack. The branch is covered by unit tests in `app/lib/__tests__/session.test.ts` (including id encoding), and by `e2e/auth.spec.ts`, whose fresh signup exercises the zero-board branch. A live one-board walk is worth doing on preview.
- `design:audit` could not see any of this before today — it followed the gate's redirect and measured `/login` while printing the requested URL in its header, so `/boards` and `/link` returned byte-identical "passing" reports about a page nobody asked about. Fixed in the same PR: `--sign-in <email>:<password>`, and exit 2 when `--scope` matches nothing.

## Verdict rationale

PASS. The feature's three claims are each checked by something that would fail if they regressed rather than by inspection: the removed URLs have e2e tests, non-admin sign-out is driven through the real control in `e2e/auth.spec.ts` (an endpoint-level `fetch` would have tested the wrong thing, since the defect was that no *control* existed), and `resolveSignedInHome` is pure and unit-tested at all three branches. Signed-in `design:audit` on `/boards`: 3 chromatic colours, 10.16:1 body contrast, no overflow at 390 or 1440, HARD checks pass.
