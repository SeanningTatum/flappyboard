## Note on the two re-checks

The first scripted run reported FAIL on `A1.signup-carries-next` and `A5.auto-manual-escape`. Both were driver artifacts, not app behavior: the script read `page.url()` after `waitForLoadState("networkidle")`, which returns immediately when the page is already idle — before the client-side navigation the click triggers has started. A targeted re-run with `Promise.all([waitForURL(...), click(...)])` showed the app doing exactly the right thing (sign-up href `/sign-up?next=%2Flink%3Fcode%3DXPNUX4`; manual escape landing `/link?code=5S8FXZ&manual=1` with prefilled picker). The follow-on assertions in the same run had already proven both flows functionally (registration succeeded through that sign-up page; the picker rendered after the escape click). No app change was needed.
