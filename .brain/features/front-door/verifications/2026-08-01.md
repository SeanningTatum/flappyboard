## Design critique — four rounds across two surfaces

`design-critic` judges the render, never the source, and its verdict is blocking. It returned **DO NOT SHIP** on both surfaces before passing either.

**Landing, round 1 → DO NOT SHIP, five P1s.** All nine anti-slop tells passed; it failed because *"its own structural claim is the worst-executed thing on it."* The typed state — the page's entire proof — was its ugliest frame at 83% dead tiles; the field carrying that claim measured 1.14:1 fill and 1.42:1 boundary, failing WCAG 1.4.11; the board and the field sat 385px apart on the primary viewport, so the memorable move happened off-screen at the moment it happened.

**Landing, round 2 → SHIP.** *"Three separate fixes converged into one gesture, which is what a designed page does and a patched one does not."*

**Auth, round 1 → DO NOT SHIP, five P1s.** The board was a decorative header strip on the two states almost everyone sees — slop risk #1 named verbatim in this feature's own lock. Dark mode measured 1.00:1 band-vs-canvas, the landing's own defect unpropagated one tap downstream. The 1440 right pane was 87% void with a rule drawn down the middle. Sign-in dead-ended while its spare space held the landing's acquisition copy. A selected tab and the primary action shared a fill **and** a label.

**Auth, round 2 → SHIP.** It re-derived the numbers rather than accepting them, and confirmed the shared-chassis division: *"three properties the auth page owns outright… shared chassis, auth-owned idea. Round 1's charge no longer stands."*

## Findings for main thread

- **The dark band interior is still exactly 1.00:1 and was deliberately not fixed.** Every tonal step in the dark palette measures 1.18–1.23:1 against the canvas, so a fill would have been *weaker* than the boundary it replaced, and inventing a token was out of scope. What changed is the boundary (1.29:1 → 1.843:1, 1px → 3px) and the plate. The critic accepted it: *"the device moved rather than the value; that is a legitimate answer."* Recorded as partial, not as fixed.
- **The funnel got colder, measured.** Landing 0.226% chromatic pixels → one tap → sign-up **0.000%**, at every viewport and both themes. The decorative greeting's amber was correctly removed and nothing replaced it. The critic held this at P2 because *"coldness is not sloppiness"* — but the answer to "did it improve" is no, it was resolved by subtraction. **This is a brief question for the owner, not a defect**, and it is the same residual the landing page carries: the household lives entirely in the copy, which is a consequence of the no-imagery lock.
- **Three defects this session were invisible to every automated gate**, and all three are the same family — something that renders is not something that works:
  1. A README hero image that was a Cloudflare Workers runtime error page. The capture script called it clean because it only watched the console, and a hung Worker serves an error page with a silent console.
  2. A `zh` screenshot that was the locale endpoint's JSON response, because the capture POSTed to the endpoint instead of driving the real control.
  3. The auth `links` export dragging `i18n.server` into the browser, **unhydrating the whole auth surface** while still rendering and still screenshotting.
  The capture scripts now refuse to shoot unless route-specific testids are present and the flap font reports loaded. There is no equivalent guard for #3 beyond the e2e suite.
- **Not verified and still owed:** the physical-TV check. `FlapWord` states its size as explicit width/height rather than `aspect-ratio` because the Tizen panel is Chromium 56 — reasoning from a documented constraint, not a measurement on the glass.

## Verdict rationale

PASS. Every claim above was driven through the live app rather than read: the typed board's row placement is pinned by four new unit tests, the CJK refusal is read back off the DOM with the input value printed beside it, the pairing arrival is captured with the code visible in tiles, and every contrast number was measured by rasterising the colour through a canvas — because Chromium serialises `oklch()`-authored colours as `oklch()`, and a regex over that string reads lightness as a red channel, which produced a full set of nonsense numbers on the first attempt.

Two items are carried forward rather than claimed: the dark band interior, and a password-reset route that does not exist and is now stated on the page rather than implied by a dead link.
