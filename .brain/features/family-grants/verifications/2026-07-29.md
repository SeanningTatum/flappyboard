## Findings for main thread

1. **The `role="alert"` error line is unreachable from whitespace input alone.**
   The client trims and disables SAVE, so the server-side `ValidationError` for
   whitespace can never be surfaced *as the alert line* from real usage — it
   only fires on refusals that survive client validation (revocation races, as
   in E4). Not a bug: the refusal is enforced at two layers and each was
   measured. Recorded so the next walk doesn't type spaces, see no alert, and
   record a false failure.
2. **Revoke-all leaves dead phones' rows in the owner list.** After the E4
   `grantEpoch` bump, the list still showed phone B's and phone C's rows
   (two "Unnamed phone" rows next to phone D's "Ari's phone"). Per-row un-pair
   removes its row (observed: 2 → 1 in claim (d)); the epoch bump kills
   credentials but does not sweep device records. Plausibly designed (records
   outlive credentials), but an owner looking at the list after a revoke-all
   sees phones that can no longer write. Owner call whether the list should
   say so.
3. **First-attempt artifact, not reproduced.** The first script run logged one
   React dev-mode hydration warning (inline `style` serialization: hex prop vs
   `rgb()` in the DOM attribute) on phone A's initial cold-compile load, while
   Playwright was interacting mid-hydration. The clean re-run — five controller
   loads including an owner probe *without* the prompt and a reload — produced
   zero jsErrors, so it is recorded as a transient of driving the page during
   hydration (same category as 2026-07-28 Finding 2), not attributed to this
   delta. The hydration-wait discipline that avoided it is now in this doc for
   reuse.

## Verdict rationale

PASS. All five claims were measured on the live app: the prompt's offer and its
permanent absence after naming (a), the name landing in the owner's list (b),
rows becoming distinguishable where the previous walk measured them identical
(c), and — the point of the whole feature — the owner un-pairing *"Kai's phone"*
by name and exactly that phone taking a 401 while its sibling wrote with a 200
(d). The whitespace refusal is enforced at both the client and server layers and
each layer was measured independently (disabled button; 400 on the wire), and
the alert surface was proven against a refusal the UI can actually produce (e).
Finding 1 from 2026-07-28 is closed; decision 4 is now reachable from the UI.
