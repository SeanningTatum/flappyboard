| 2026-07-28 | security | **Spend caps on the two paid endpoints — issue #1 closed, the last blocker on a real-key deploy.** The attack it answers: photograph the TV, redeem the QR, then loop `board.generate` (1–3 `claude-sonnet-5` calls at `max_tokens: 4096`, billed to the owner's `ANTHROPIC_API_KEY`) or `POST /api/transcribe` (1 MiB of audio through Whisper, billed to the `AI` binding). Authorisation was never the hole — it is correct and runs before the body is read — a legitimately paired phone was simply unbounded, and `grep -rn "rate.?limit\|throttl"` across the repo returned nothing. Now an atomic check-and-increment in the board's `BoardRoom` Durable Object, which needs **no new binding**: it is already the single-threaded authority per board, and the counter runs under the same `blockConcurrencyWhile` the spent-nonce ledger uses, so N phones pressing the button together cannot lose increments to a race. **Two buckets, and a call must clear both.** Per-spender, keyed by the random nonce inside the caller's grant (a caller cannot choose it, forge another's, or strip it without invalidating the token that carries it), so one guest cannot eat another's allowance and the owner's budget is separate. Per-board behind it as the hard ceiling, because per-spender alone is bypassable by re-pairing — every fresh redemption mints a fresh nonce and therefore a fresh allowance. Defaults per hour: 20/60 generations (spender/board), 60/200 transcriptions. Fixed windows, not a sliding log: a boundary allows up to 2× burst, which is the right trade for two integers of storage against a cap whose job is bounding a runaway bill, not smoothing traffic. **Fails closed everywhere** — an unreachable or unparseable ledger raises `ExternalServiceError` rather than answering `allowed: true`, and a refused call increments nothing (counting refusals would let someone already over the limit hold the board bucket down on traffic that cost nothing). New `RateLimitError` → `TOO_MANY_REQUESTS`; `/api/transcribe` is not a tRPC route so it answers 429 with a `Retry-After` header, charged *after* the free content-type/length checks (a 415 must not burn allowance) and *before* the body read (an over-cap caller must not push a megabyte through the isolate). 849 → 892 tests. See `.brain/features/llm-board-agent/llm-board-agent.md` and issue #1. |

| 2026-07-27 | security | **Pre-PR hardening pass on the pairing surface (12 findings from an adversarial review, all fixed).** Headline: **controller grants are now revocable.** A new `board.grantEpoch` column (migration `0002_long_deathstrike`) is inside the HMAC signing message of *both* the pairing token and the grant, and owner-only `board.revokeControllers` (`protectedProcedure` + `requireOwnedBoard` — a grant must never revoke grants) increments it, killing every outstanding grant for **that board only**. Before this the only revocations available were deleting the board or rotating `BETTER_AUTH_SECRET`, which signs out every user of the deployment. Surfaced as `Unpair phones` on the `/boards` card. Also closed: **production stack traces** — tRPC resolved `isDev` from `NODE_ENV`, which Workers does not guarantee and `wrangler.jsonc` never set, so `data.stack` was reaching unauthenticated callers of `pair`/`claim`; now `isDev: import.meta.env.DEV` (proven `const isDev = false` in the built bundle, with the dev-only random sleep dead-code-eliminated) plus a formatter that strips `stack` unconditionally. **A 100MB chunked body buffered before its 413** — `Number(null) === 0` let a missing `Content-Length` past, and the real check ran after `arrayBuffer()`; now a counting `TransformStream` aborts at the cap. **A board-existence oracle** at all three grant sites: with any session plus a junk grant cookie, a real foreign id gave 401 and an invented id gave `board not found: <id>` — the refusal now depends only on whether a cookie was sent. **`history` handed a guest the owner's pre-pairing prompts** — it is now floored at the grant's own `issuedAt`. **One injected cookie could DoS pairing** (a sibling `*.workers.dev` host setting `fb_grant_<id>` on a parent domain) — every cookie of that name is now a candidate. Plus: the nonce is spent *last* in `pair` so a DO hiccup no longer burns a token and issues nothing; a transient `claim` failure no longer destroys a valid grant; `ConfigurationError` stopped naming which secret is missing; `new Anthropic()` can no longer defect the whole runtime; and a raw `try/catch` left `app/lib/`. 811 → 849 tests.
